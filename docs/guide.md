# xlCode の使い方

xlCode は、Excel の Copilot に書かせたコードを、パソコン上のソースコードのファイルとつなぐアプリです。
Excel のブック（編集用ブック）の 1 シートが、ソースコードの 1 ファイルに対応します。

- Copilot がシートに書いたコードを、ファイルに書き出す操作が **Build**（Excel → ソースコード）
- エディタで直したファイルを、シートに書き戻す操作が **Sync**（ソースコード → Excel）

迷ったら、ブック画面の上にある **「次の操作」** を見てください。今すべきことを 1 つだけ示し、対応するボタンを青く強調します。

## はじめに

### 用意するもの

| もの | 必要な理由 |
|---|---|
| Windows のパソコン | xlCode は Windows 用です |
| Excel（デスクトップ版・Web 版のどちらか、または両方） | ブックを開いて Copilot に編集させるため |
| OneDrive（会社の OneDrive for Business など） | Web 版の Excel と Copilot でブックを開くには、ブックが OneDrive にある必要があります |
| Git（おすすめ） | Build / Sync の前に自動でコミットし、いつでも前の状態に戻せるようにするため。無くても使えますが、そのたびに確認が出ます |

VBA のツールを作る場合（[VBA モード](#vba-モード)）は、さらに **Windows のデスクトップ版 Excel** と、Excel の設定「**VBA プロジェクト オブジェクト モデルへのアクセスを信頼する**」が必要です。

### 用語

| 用語 | 意味 |
|---|---|
| プロジェクト | ソースコードを置いているフォルダ。xlCode では 1 つのフォルダを開いて作業します |
| 編集用ブック | `（フォルダ名）.xlcode.xlsx` という名前のブック。フォルダ 1 つにつき 1 冊作ります。Copilot に編集させるのはこのブックです |
| コードのシート | 名前に拡張子がある（`App.tsx`、`run.bat`、`Module1.bas` など）シート。同じ名前のファイルと 1 対 1 で対応します |
| Excel 側 | 編集用ブックのシートの内容 |
| ソース側（エディタ側） | パソコン上のファイルの内容 |
| `#tree` シート | プロジェクト全体のフォルダ構成。Copilot がほかのファイルの場所を知るために使います。xlCode が自動で書くので、編集しないでください |
| `Agents.md` / `LocalAgents.md` | Copilot に守らせたいルールを書くファイル。[ルール](#ルールagentsmd--localagentsmd)を参照 |
| 衝突 | 同じファイルを、Excel 側とソース側の両方で変更した状態。[衝突の解決](#衝突の解決)を参照 |

## 最初の準備

### 1. プロジェクトを開く

1. xlCode を起動し、「**プロジェクトを開く...**」（または左下のフォルダのアイコン、`Ctrl+O`）を押します。
2. ソースコードのフォルダを選びます。
3. 初めて使うときは「**どの Excel でブックを編集しますか？**」と聞かれます。

| 選択肢 | こんなときに | 動き |
|---|---|---|
| 両方 | 迷ったらこれ | デスクトップ版で開いているかは自動で検知します。Web 版で開いた可能性があるときだけ、Build / Sync の前に「閉じましたか？」と確認します |
| デスクトップ版のみ | Web 版を使わない | 開いているかを自動で検知し、開いていれば Build / Sync を止めます。確認は出ません |
| Web 版のみ | ブラウザだけで作業する | Web 版で開いているかは検知できないため、Build / Sync の前に毎回「閉じましたか？」と確認します |

この設定はパソコンごとです。あとから[設定](#設定)やステータスバーの「Excel: 〜」で変えられます。

一度開いたプロジェクトは、起動画面の「**最近使用したプロジェクト**」から開けます（最大 8 件）。

### 2. 最初のブックを作る

1. 左のサイドバーの「**ブック未作成のディレクトリ**」に、ブックがまだ無いフォルダが並びます。
2. 作りたいフォルダの行にマウスを乗せ、右端の **＋** を押します。
   - 見出しの **＋** を押すと、一覧のすべてのフォルダにまとめて作れます（ソースコードモードのみ）。
3. 初めてのブックでは、次の 2 つを聞かれます。

**プロジェクトの種類**（あとから変えられません）

| 種類 | 用途 |
|---|---|
| ソースコード | ふつうのプログラム（TypeScript、Python、バッチファイルなど）。1 シート = 1 ファイル |
| VBA | Excel のマクロのツール。画面・データのシートと VBA のコードを 1 冊で編集し、Build で `.xlsm` を作ります。[VBA モード](#vba-モード)を参照 |

**編集用ブックの置き場所**

| 選択肢 | 説明 |
|---|---|
| OneDrive のフォルダを選ぶ…（おすすめ） | OneDrive の中に、このプロジェクト専用のフォルダ（例: `OneDrive\xlCode\shop`）を作って選びます。ブックだけがそこに置かれ、ソースコードと Git は今のフォルダに残ります |
| プロジェクトの中に置く | 各フォルダの中にブックを置きます。プロジェクト自体が OneDrive の中にある場合や、デスクトップ版だけで使う場合に |

4. 確認画面で「**作成**」を押すと、フォルダ内のファイルが 1 つずつシートとして取り込まれます。

このとき、xlCode は次の準備も自動で行います。

- `.gitignore` に `*.xlcode.xlsx`、`~$*`、`.xlcode/` を追記（ブックや作業用のファイルを Git に入れないため）
- プロジェクトの一番上に `Agents.md`、各フォルダに `LocalAgents.md` の雛形を作成（すでにあれば何もしません）
- ブックの先頭に `#tree` シート、続けて `Agents.md` シートを作成

> **ブックの置き場所の例**
>
> ```
> C:\dev\shop\                       ← ソースコード（OneDrive の外）。Git もここ
>   app\App.tsx
> OneDrive - 会社\xlCode\shop\       ← 編集用ブックだけ
>   app\app.xlcode.xlsx              ↔ C:\dev\shop\app\ のファイル
> ```
>
> ソースコード・`.git`・`node_modules` を OneDrive に置くと同期が重くなり、`.git` が壊れやすくなります。ブックだけを OneDrive に置くのがおすすめです。

### 取り込まれないファイル

- 拡張子の無いファイル（`Makefile`・`Dockerfile`・`LICENSE`・`README` などの決まった名前を除く）
- `.gitignore` で除外しているファイル
- 画像などのバイナリファイル、文字コードを判定できないファイル
- 名前がシート名に使えないファイル（[シート名の決まり](#シート名の決まり)）。この場合はブックを作らずに止まります。対象外にするには `.gitignore` に追加してください

取り込まなかったファイルは、作成後のブック画面と出力パネルに理由つきで表示されます。

## 基本の流れ

毎日の作業は、次のくり返しです。

1. **Excel で開く** — ブック画面の「デスクトップで開く」または「Webで開く」を押します。エディタでの変更がシートにまだ入っていなければ、開く前に自動で Sync するので、変更も入った状態で開きます。
2. **Copilot に編集させる** — たとえば「App.tsx にログイン画面を追加して」と頼みます。
3. **Excel を閉じる** — デスクトップ版はブックを保存して閉じます。Web 版はブラウザのタブを閉じます。
4. **Build** — Copilot が書いた変更が、ソースコードのファイルに書き出されます。
5. エディタ（VS Code など）で動かして確かめる・直す。
6. エディタで直したら **Sync**（または次に「開く」を押せば自動で Sync されます）。

> **大事なこと**
>
> Build / Sync / 元に戻す は、ブックを**閉じてから**実行してください。開いたまま実行すると、Excel の保存と xlCode の書き込みがぶつかり、片方の変更が丸ごと失われます。
> デスクトップ版で開いているときは xlCode が自動で止めますが、Web 版で開いているかは検知できません。

## 画面の見方

画面は、次の 5 つの部分でできています。

| 場所 | 名前 | 内容 |
|---|---|---|
| 左端の細い列 | アクティビティバー | 画面の切り替え（エクスプローラー・ルール・ヘルプ・設定） |
| 左 | サイドバー | ブック一覧と、ブック未作成のディレクトリ |
| 中央 | ブック画面 | ボタン、お知らせ、次の操作、ファイル一覧 |
| 中央の下 | パネル | 問題と出力（操作の記録） |
| 最下部 | ステータスバー | Git、エラーの数、OneDrive、使う Excel など |

### アクティビティバー（左端）

| アイコン | 内容 |
|---|---|
| ファイル | エクスプローラー（ブック一覧とブック画面） |
| 文書 | ルール（`Agents.md` / `LocalAgents.md` の編集） |
| ？ | このヘルプ（`F1`） |
| 歯車 | 設定 |
| フォルダ | プロジェクトを開く（`Ctrl+O`） |

### サイドバー: ブック一覧

プロジェクトのブックが、フォルダの階層に沿って並びます（ブックの無いフォルダが 1 つずつ続くところは `pkg/web/src` のように 1 行にまとめます）。フォルダの行を押すと開閉でき、閉じたフォルダには中のブックの数が出ます。ブックの行を押すとブック画面を表示し、左の矢印でシート（ファイル）の一覧を開閉できます。

行の右端のしるし:

| しるし | 意味 |
|---|---|
| 鍵 | デスクトップ版 Excel で開かれています。Build / Sync はできません |
| 雲 | OneDrive の同期状態（色で状態を表します。マウスを乗せると表示） |
| 赤い ⓧ | エラーがあります |
| `C2` | 両側で変更されたファイルが 2 つ（衝突） |
| `E3` | Excel 側で編集されたファイルが 3 つ（Build で反映） |
| `S1` | エディタ側で変更されたファイルが 1 つ（Sync で反映） |

見出しにマウスを乗せると出るボタン:

- **Refresh Tree**（木のアイコン）: 全ブックの `#tree` と `Agents.md` シートを最新にします。[Refresh Tree](#refresh-tree)を参照
- **再読み込み**: ファイルとブックの状態を読み直します。ふだんは xlCode のウィンドウに戻ったときに自動で読み直すので、表示が古いときだけ使います

### サイドバー: ブック未作成のディレクトリ

ブックがまだ無いフォルダが、フォルダの階層に沿って並びます（最初は閉じています）。行にマウスを乗せると出る **＋** でそのフォルダのブックを作ります。

### ブック画面

上から順に次のものが並びます。

**パンくず** — ブックのある場所。

**ツールバー**

| ボタン | 内容 |
|---|---|
| デスクトップで開く / Webで開く | Excel で開きます。シートに入っていないエディタ側の変更があれば、先に Sync します。「使う Excel」が片方だけのときは「Excelで開く」の 1 つだけになります |
| Build（Excel → ソース） | Excel 側の変更をファイルへ書き出します。数字は反映待ちのファイル数 |
| Sync（ソース → Excel） | エディタ側の変更をシートへ書き戻します。数字は反映待ちのファイル数 |
| 元に戻す | 直前の Build / Sync を取り消します（直前の操作があるときだけ表示） |
| ビルド結果を開く | VBA モードのみ。作った `.xlsm` をデスクトップ版 Excel で開きます |
| ターミナル | このフォルダで Windows Terminal（無ければコマンドプロンプト）を開きます |
| フォルダ | エクスプローラーでブックの場所を開きます |

押せないボタンは、マウスを乗せると理由が出ます（「処理中です」「デスクトップ版 Excel で開かれているため実行できません」など）。

**お知らせ** — 必要なときだけ出ます。

| お知らせ | 対応 |
|---|---|
| ブックを読み込めません | ブックが壊れているか、Excel の形式ではありません。「フォルダ」から実物を確認してください |
| OneDrive が起動していません | OneDrive を起動してください |
| OneDrive: アップロード待ち / 同期中 など | Build / Sync / 開く は、同期が終わるまで自動で待ちます |
| OneDrive: 同期が一時停止中 / 同期エラー | OneDrive の画面で状態を確認してください |
| このブックはデスクトップ版 Excel で開かれています | Excel を閉じると自動で消えます |
| 未解決の衝突シートがあります | [衝突の解決](#衝突の解決)を参照 |
| #tree が最新ではありません | 右の「Refresh Tree」を押します |
| 削除マーク付きのシート | 次の Build で、確認のうえファイルとシートを削除します |
| ビルド結果: 〜 | VBA モードのみ。[ビルド結果の使い方](#ビルド結果の使い方)を参照 |
| 〜 完了 / 中断しました など | 直前の操作の結果。「変更したもの」を開くと、書き出したファイルや更新したシートの一覧が見られます。× で閉じられます |

**次の操作** — 電球のアイコンの行です。今すべきことを 1 つだけ示し、必要ならその場で押せるボタンを付けます。表示は次の順に決まります。

1. 処理中 → 終わるまで待つ
2. エラーがある → エラーを直す
3. デスクトップ版で開かれている → Excel を閉じる
4. 衝突シートが残っている → Excel で統合してから Build
5. 両側で変更されたファイルがある → Build で衝突シートを作る
6. Excel 側の変更がある → Build
7. エディタ側の変更がある → Sync
8. フォルダ構成が変わった → Refresh Tree
9. すべて同期済み → Excel で開いて Copilot に編集させる

**集計** — 「Excel側で編集中」「エディタ側で変更」「両側で変更」「同期済み」のファイル数。

**ファイル一覧** — シート（ファイル）ごとの[状態](#ファイルの状態)・文字コードと改行（形式）・次にすべき操作。

### 変更を確認する（差分）

Build や Sync で何が変わるかを、実行する前に確かめられます。

- 変更のある行を押すと、その下に差分を表示します。もう一度押すと閉じます。
- 表の見出しの「**変更を確認**」で、変更のあるすべてのファイルの差分を開きます（「差分を閉じる」で全部閉じます）。
- 緑の `+` 行が追加、赤の `−` 行が削除です。右端に追加・削除の行数が出ます。
- 見出しの説明（例:「Build 後のソースファイル: ソース側の現在 → Excel 側の内容」）で、どちらからどちらへ反映されるかがわかります。
- 「内容は同じです（整形の違いのみ）」と出る場合は、空白や改行など整形の違いだけです。

### パネル（問題 / 出力）

画面下のパネルです。`Ctrl+J` で開閉します。

- **問題**: 全ブックのエラーと警告の一覧。ステータスバーの ⓧ / ⚠ の数を押しても開きます。
- **出力**: 操作の記録（何を書き出したか、警告、エラー）。右上の × で消去できます。

### ステータスバー（最下部）

| 表示 | 意味 |
|---|---|
| ブランチ名（`*` 付き） | Git のブランチ。`*` は未コミットの変更があること |
| Git なし | Git で管理されていないフォルダです。Build / Sync 前のバックアップが作られません |
| ⓧ 0 ⚠ 0 | エラーと警告の数。押すと「問題」を開きます |
| Excel側で編集中: 3 | Build 待ちのファイル数（全ブック合計）。マウスを乗せるとファイル名 |
| #tree 最新 / #tree 古い (2) | `#tree` が古いブックの数 |
| OneDrive: 同期済み など | 全ブックのうち、いちばん注意が必要な同期状態。押すと詳しい状態を出力パネルに出します |
| Excel: 両方 など | 使う Excel。押すと設定を開きます |

## 各操作の詳しい説明

### Excel で開く

「デスクトップで開く」「Webで開く」は、シートに入っていないエディタ側の変更（または両側の変更）があるとき、次をまとめて行います。

1. ブックが閉じていること、OneDrive の同期が終わっていることを確かめる
2. **Sync**（エディタ側の変更をシートへ）
3. Web 版の場合は、書き換えたブックが OneDrive にアップロードされるまで待つ
4. Excel で開く

そうした変更が無ければ、ブックを書き換えないので、確認も Sync もせずにそのまま開きます。

Web 版は、ブックの場所から OneDrive / SharePoint の URL を自動で求めて、既定のブラウザで開きます（日本語の同期フォルダ名でもかまいません）。個人用 OneDrive（Microsoft アカウント）は、OneDrive がこの PC に持つ同期の情報からブックの ID を調べて開きます（調べられなければ OneDrive の「オンラインで表示」を使います）。OneDrive がまだブックを同期していないと開けないので、エクスプローラーでブックに緑のチェックが付いてから開いてください。求められないときは「Web 版で開けませんでした」と、見つかった同期フォルダが出るので、「設定を開く」から [Web 版の URL](#このプロジェクトの設定) を入力してください。

### Build

**Excel 側の変更を、ソースコードのファイルに書き出します。**

- Excel 側で変更・追加されたシート → ファイルを書き出す（新しいシートなら新しいファイルを作る）
- ソース側だけで変更されたファイル → ついでにシートへ取り込む（Build は Sync も兼ねます）
- シート名の先頭が `DEL_` のシート → 確認のうえ、ファイルとシートを削除する
- 両側で変更されたファイル → 何も書き出さずに[衝突シート](#衝突の解決)を作って止まる
- 書き出したファイルは、元の文字コード・改行コードのまま保存します（[文字コードと改行](#文字コードと改行)）

実行前に、必要に応じて確認が出ます（[確認画面](#確認画面の一覧)）。未解決の衝突シートがあると Build できません。

### Sync

**エディタ側の変更を、シートに書き戻します。**

- ソース側で変更・追加されたファイル → シートを書き換える・作る
- ソース側で削除されたファイル → シートを削除する
- Excel 側でシートを消してしまったファイル → シートを復元する
- 両側で変更されたファイル → 衝突シートを作る

Excel 側にまだ Build していない変更があると、次のどれかを選ぶ画面が出ます。

| 選択肢 | 動き |
|---|---|
| 先に Build してから Sync（おすすめ） | Excel 側の変更をファイルへ書き出してから Sync します |
| シートの変更を破棄して Sync | Excel 側の変更を捨てて、ソース側の内容でシートを上書きします |
| 中止 | 何もしません |

`DEL_` の付いたシートは Sync では処理しません（次の Build で処理します）。

### 元に戻す

**直前の Build / Sync を 1 回だけ取り消します。**

- ブック、Build が書き出した・削除したファイル、xlCode の記録（`.xlcode/state.json`）を、操作の直前の状態に戻します。VBA モードでは `.xlsm` も戻します。
- 戻せるのは、ブックごとに**直前の 1 回だけ**です。戻したあとはボタンが消えます。
- 操作のあとに、それらのファイルやブックへ加えた編集は失われます。
- Git の自動コミットは取り消されません（コミットは残ったままです）。
- ブックを Excel で開いていると戻せません。

もっと前の状態に戻したいときは、ソースコードは Git の履歴から、ブックは OneDrive のバージョン履歴から戻してください。

### Refresh Tree

**全ブックの `#tree` シートと `Agents.md` シートを最新にします。**

- ファイルを追加・削除・移動したあとに実行すると、Copilot がプロジェクトの最新の構成を知ることができます。
- ルートの `Agents.md` を変更したあとに実行すると、全ブックの `Agents.md` シートに配られます。
- プロジェクトを開いたときにも自動で実行します。
- すでに最新のブックは保存しません（Web 版で編集中のブックと同期がぶつからないように）。
- Excel で開いているブックは更新できません。「一部のブックだけ更新されました」と出たら、Excel を閉じてもう一度実行してください。

## Excel でシートを編集するときの決まり

Copilot にも守らせる必要があるので、[Agents.md](#ルールagentsmd--localagentsmd) にも書いておくと確実です（雛形に入っています）。

### 1 シート = 1 ファイル

- シートの名前が、そのままファイル名になります（拡張子も含めて）。例: `App.tsx` シート ↔ `App.tsx` ファイル
- **A 列に、1 行ずつ**コードを書きます。1 つのセルが 1 行です。
- B 列より右に書いた内容は無視されます（警告が出ます）。
- 空のセルは空行になります。
- セルは「文字列」として扱います。Excel が数値や日付に自動で変えてしまったセル（例: `007` → `7`）があると、Build はエラーで止まります。`'` を先頭に付けるか、セルの書式を「文字列」にしてください。
- 1 つのセルに入るのは 32,767 文字までです。

### ファイルを増やす・消す

| したいこと | 方法 |
|---|---|
| ファイルを追加 | そのファイル名のシートを作り、A 列に書いて Build |
| ファイルを削除 | シート名の先頭に `DEL_` を付けて（例: `DEL_old.ts`）Build。確認のうえ、ファイルとシートを削除します |
| ファイル名を変える | 新しい名前のシートを作って中身を移し、古いシートに `DEL_` を付けて Build |

> **注意**
>
> シートを削除しただけでは、ファイルは削除されません。次の Build / Sync でシートが**復元**されます（ファイルの状態が「シートが削除された」になります）。削除するときは必ず `DEL_` を使ってください。

### シート名の決まり

- 拡張子を含めて **31 文字以内**（Excel の制限）。`DEL_` を付けるので、実際には 27 文字以内にしておくと安心です
- 使えない記号: `: \ / ? * [ ]`、および Windows のファイル名に使えない `< > " |`
- 先頭・末尾に `'` は使えません。末尾が `.` や空白の名前、`CON`・`NUL` などの Windows の予約名も使えません
- 大文字と小文字だけが違う名前（`app.ts` と `App.ts`）は同時に使えません

### さわらないシート

| シート | 理由 |
|---|---|
| `#` で始まるシート（`#tree` など） | xlCode が管理します。`#conflict_01` などの衝突シートだけは、統合のために編集・削除します |
| `Agents.md` | ルートの `Agents.md` から配られるコピーです。シートを変更しても反映されません（警告が出ます）。エディタか xlCode の「ルール」で編集してください |

### コード以外のシート

拡張子の無い名前のシート（`UI`、`データ` など）はコードとして扱わず、xlCode は一切さわりません。画面や説明用のシートを自由に置けます。
拡張子の無いファイル名をコードとして扱いたい場合は、`.xlcode/config.json` の `extraCodeNames` に名前を追加してください（例: `"extraCodeNames": ["Taskfile"]`）。

## ファイルの状態

ブック画面とサイドバーには、ファイルごとの状態が 1〜2 文字で表示されます。xlCode は前回の Build / Sync のときの内容を覚えていて、それと比べて判断します。

| 表示 | 状態 | 意味 | 次の操作 |
|---|---|---|---|
| （✓） | 同期済み | 両側が同じ | なし |
| `E` | Excel側で編集中 | シートだけが変わった | Build でファイルへ |
| `E+` | Excel側で新規作成 | 新しいシートがある | Build でファイルを作る |
| `S` | エディタ側で変更 | ファイルだけが変わった | Sync でシートへ |
| `S+` | エディタ側で新規作成 | 新しいファイルがある | Sync でシートを作る |
| `D` | エディタ側で削除 | ファイルが消された | Sync でシートを削除 |
| `!` | シートが削除された | シートだけが消された | Sync で復元（削除したいなら `DEL_`） |
| `C` | 両側で変更 | シートとファイルの両方が変わった | Build / Sync で衝突シートを作る |

整形（空白やインデント）の違いだけの場合は、変更として扱いません。

## 衝突の解決

同じファイルを Excel 側とソース側の両方で変更すると、Build / Sync のときに**衝突シート**（`#conflict_01` など）を作って止まります。どちらの変更も失われません。

衝突シートの中身:

|  | A 列 | B 列 |
|---|---|---|
| 1 行目 | ファイルの場所（例: `app/App.tsx`） | やること（「A列とB列を統合して…」） |
| 2 行目 | `Excel側` | `ソース側` |
| 3 行目〜 | Excel 側の内容 | ソース側の内容 |

解決の手順:

1. ブックを Excel で開きます（衝突シートは Build / Sync のときにすでに保存されています）。
2. Copilot に次のように頼みます。
   「**#conflict_01 シートの A 列（Excel 側）と B 列（ソース側）を統合して App.tsx シートに書き、#conflict_01 シートを削除して**」
3. 結果を確かめて、Excel を閉じます。
4. **Build** します。統合した内容がファイルに書き出されます。

衝突シートが残っているあいだは Build できません。自分で統合してもかまいません（元のシートに統合結果を書き、衝突シートを削除します）。

## 確認画面の一覧

| 確認 | いつ出るか | どうすればよいか |
|---|---|---|
| Web 版 Excel でこのブックを閉じましたか？ | 「使う Excel」が「Web 版のみ」、または「両方」で xlCode からデスクトップ版で開いていないときの Build / Sync の前（「開く」では、先に Sync するときだけ） | ブラウザのタブを閉じ、OneDrive の同期が終わってから「閉じたので続行」。「アプリを閉じるまで確認しない」にチェックすると、そのブックでは聞かれなくなります（Web で開き直すと、また聞かれます） |
| 未コミットの変更があります。実行前に自動コミットします | そのフォルダに Git の未コミットの変更があるとき | 続行すると、今の状態を `xlcode: Build 前の自動コミット` などの名前でコミットしてから実行します |
| Git リポジトリではないため、実行前のバックアップが作られません | Git で管理していないとき | そのまま続行できます。バックアップを残したい場合は、フォルダで `git init` してください |
| コードが大きく減っています。Copilot が省略した可能性があります | 前回から行数か文字数が大きく減ったとき（初期値: 30% 以上、前回 10 行以上のファイル） | 差分を確認してください。Copilot が「…（省略）…」のようにコードを縮めていることがあります。意図した削除なら続行 |
| 次のファイルとシートを削除します | `DEL_` の付いたシートがあるとき | 一覧を確認して続行 |
| Excel 側に Build していない変更があります | Sync のとき | [Sync](#sync)を参照 |
| OneDrive が起動していません / 同期が一時停止中 / 同期エラー | OneDrive の状態に問題があるとき | 「キャンセル」して OneDrive を確認するのがおすすめです。「このまま〜」で続けることもできます |
| OneDrive の同期が終わりません | 2 分待っても同期中のとき | エクスプローラーや OneDrive の画面で状態を確認してください |
| Web 版での編集が、まだこの PC に届いていない可能性があります | Web 版で開いたあと、ブックが一度も更新されていないとき | Web 版で編集したなら「届くまで待つ（最大2分）」。何も編集していなければ「編集していないので〜」 |
| 両側で変更されたファイルがあります | 衝突シートを作ったとき | [衝突の解決](#衝突の解決)を参照 |

赤いボタン（「続行」「元に戻す」など）は、元に戻しにくい操作です。内容をよく確認してから押してください。

## ルール（Agents.md / LocalAgents.md）

Copilot に守らせたいルール（使う言語、書き方、フォルダの構成など）を書くファイルです。アクティビティバーの「ルール」で編集できます。

| ファイル | 範囲 | ブックへの反映 |
|---|---|---|
| `Agents.md`（プロジェクトの一番上） | プロジェクト全体 | 保存後に **Refresh Tree** を実行すると、全ブックの `Agents.md` シートに配られます |
| `LocalAgents.md`（各フォルダ） | そのフォルダ（ブック）だけ | 保存後に **Sync** すると、そのブックの `LocalAgents.md` シートに反映されます |

- 左の一覧でファイルを選び、右で編集して「**保存**」（`Ctrl+S`）します。ファイルがまだ無ければ、保存したときに作ります。
- 保存していないファイルには `●` が付きます。別のファイルや画面に切り替えても、編集内容は残ります。保存しないままアプリやプロジェクトを閉じようとすると確認が出ます。
- 編集中に、エディタなどでファイルが変更されると知らせが出ます。「編集を破棄して読み込み直す」で、ほかで変更された内容を読み込めます。
- `Agents.md` は **100 行まで**を目安にしてください。長すぎると Copilot が途中で生成を止めることがあります（100 行を超えると行数が黄色になります）。
- `LocalAgents.md` はふつうのコードのシートと同じ扱いなので、Copilot に編集させて Build することもできます。

## OneDrive との付き合い方

Web 版の Excel と Copilot は OneDrive 上のブックを開くため、パソコン上のブックと同期が取れていることが大切です。xlCode はこれを見張り、必要なら待ちます。

### 同期状態の表示

ステータスバー、サイドバーの雲のアイコン、ブック画面のお知らせに表示されます（10 秒ごとに更新）。

| 表示 | 意味 | xlCode の動き |
|---|---|---|
| 同期済み | 問題なし | — |
| アップロード待ち / ダウンロード待ち / 同期中 | 転送中 | Build / Sync / 開く の前に、終わるまで自動で待ちます（最大 2 分） |
| 同期が一時停止中 | OneDrive を一時停止している | 続けるかを聞きます |
| 同期エラー | OneDrive で問題が起きている | 続けるかを聞きます |
| オンラインのみ | ファイルがパソコンにダウンロードされていない | — |
| 起動していません | OneDrive が動いていない | 続けるかを聞きます |
| OneDrive 外 | ブックが OneDrive の外にある | 表示しません |

ステータスバーの「OneDrive: 〜」を押すと、ブックごとの状態を出力パネルに出します。

### 気をつけること

- **Web 版で編集したら、タブを閉じてから少し待ちましょう。** 編集がパソコンに届く前に Build すると、古い内容で Build してしまいます。xlCode は「まだ届いていない可能性」を検知して知らせます。
- **同じブックを 2 台のパソコンで使わないでください。** xlCode の記録（`.xlcode/state.json`）はパソコンごとなので、衝突扱いになります。OneDrive が `ブック名-PC名.xlsx` のような複製を作った場合は、警告が出ます。複製の中身を確認し、必要な変更を元のブックに移してから、複製を削除してください。
- ブックの置き場所は、あとから[設定](#このプロジェクトの設定)で変えられます。既存のブックも同じフォルダ構成のまま移動します（Excel で開いているブックや、移動先に同じ名前のファイルがある場合は、何も動かさずに止めます）。

## VBA モード

Excel のマクロのツール（`.xlsm`）を、Copilot で作るためのモードです。最初のブックを作るときに「VBA」を選びます。

### しくみ

```
編集用ブック（OneDrive）  販売管理.xlcode.xlsx
  画面・データのシート（UI、マスタ など）と、コードのシート（Module1.bas など）
        │ Build ①                    ▲ Sync
        ▼                            │
ソースコード（プロジェクト）  Module1.bas など（Git で管理）
        │ Build ②（デスクトップ版 Excel で VBA を書き込む）
        ▼
ビルド結果（プロジェクト）  販売管理.xlsm（画面・データのシート + VBA）
```

- Build を押すと、①シートをソースコードに書き出し、②画面・データのシートと VBA を入れた `.xlsm` を作ります。
- ②では、画面に出ない Excel をバックグラウンドで使います（マクロは実行しません）。3 分で終わらなければ止めます。②で失敗しても、①の書き出しは済んでいて、`.xlsm` は前のままです。
- Sync（エディタで直したコードをシートへ）も使えます。`.xlsm` に入れるには、そのあと Build します。
- Windows 以外のパソコンでは Build できません（「次の操作」で知らせます）。Sync とエディタでの編集はできます。

### Excel の設定（初回だけ）

Build ②と取り込みには、次の設定が必要です。

1. デスクトップ版 Excel で「**ファイル**」→「**オプション**」を開きます。
2. 「**トラスト センター**」→「**トラスト センターの設定...**」を押します。
3. 「**マクロの設定**」で「**VBA プロジェクト オブジェクト モデルへのアクセスを信頼する**」にチェックを入れて「OK」を押します。

### シート名と VBA の対応

| シート名 | 書き込み先 |
|---|---|
| `Module1.bas` | 標準モジュール |
| `Class1.cls` | クラスモジュール |
| `UserForm1.frm` | ユーザーフォーム |
| `ThisWorkbook.cls` | ブックのコード（ブックのイベントなど） |
| `（画面のシート名）.cls`（例: `UI.cls`、`Sheet1.cls`） | そのシートのコード（シートのイベントなど） |
| `References.refs` | 参照設定 |
| 拡張子の無いシート（`UI`、`マスタ` など） | 画面・データとして `.xlsm` にそのまま入ります |

- `Agents.md`、`LocalAgents.md`、`#tree` などは `.xlsm` には入りません。
- コードの先頭に `Attribute VB_Name = ...` は書きません（書いてあれば除いて書き込みます）。
- モジュールを削除するときも、シート名に `DEL_` を付けて Build します。
- ソースコードのファイルは Shift_JIS・CRLF で保存します。

### ユーザーフォームの書き方

`.frm` のシートには、先頭にフォームの配置を書き、そのあとにコードを書きます。

```vb
Begin UserForm UserForm1
   Caption = "顧客登録"
   Width = 300
   Height = 200
   Begin TextBox txtName
      Left = 80
      Top = 12
      Width = 150
   End
   Begin CommandButton btnOK
      Caption = "登録"
      Left = 150
      Top = 150
   End
End

Private Sub btnOK_Click()
    MsgBox txtName.Value
End Sub
```

- 使えるコントロール: Label、TextBox、CommandButton、ComboBox、ListBox、CheckBox、OptionButton、ToggleButton、Frame、MultiPage（中に Page）、TabStrip、ScrollBar、SpinButton、Image
- 値は、文字列 `"…"`、数値、`True` / `False`、`&H8000000F&` のように書きます。`fmBorderStyleSingle` などの定数名は使えないので、数値で書きます。
- 画像は設定できません。必要なら Build 後の `.xlsm` で VBE から設定してください（次の Build で消えるので、ビルド結果をコピーして使う前に設定します）。

### 参照設定

Dictionary・正規表現・ADO などの外部ライブラリの使い方は 2 通りあります。**おすすめは B** です。

|  | 書き方 | 必要なこと |
|---|---|---|
| A（参照設定） | `Dim d As New Scripting.Dictionary` | `References.refs` シートにライブラリを書く |
| B（CreateObject） | `Dim d As Object: Set d = CreateObject("Scripting.Dictionary")` | なし。ほかのパソコンでも「参照不可」になりにくい |

`References.refs` には 1 行に 1 つ、`{GUID} 主.副 説明` の形で書きます（`'` で始まる行は無視されます）。よく使うライブラリの例が、ファイルの先頭のコメントにあります。

### ビルド結果の使い方

- ビルド結果（例: `販売管理.xlsm`）は、Build のたびに作り直す**ひな形**です。実際に使うときは、コピーして別の名前（例: `販売管理_2026年10月.xlsm`）にしてください。
- ビルド結果に直接データを入力したり、VBE でコードを直したりすると、次の Build で消えます。変更されている場合は、Build の前に確認が出ます。上書きする前のファイルは `.xlcode/backup/` に 5 世代まで残り、ブック画面の「**バックアップ**」でそのフォルダを開けます。
- 直前の Build は「元に戻す」で `.xlsm` ごと戻せます。
- `.xlsm` は Git で管理しません（`.gitignore` に `*.xlsm` を追加します）。画面・データのシートは編集用ブックにだけあるので、戻すときは OneDrive のバージョン履歴を使います。
- ブック画面の「**ビルド結果を開く**」でデスクトップ版 Excel で開けます。お知らせの「**フォルダ**」でファイルの場所を開けます。

> **メールなどで受け取った .xlsm のマクロが動かないとき**
>
> Windows の安全機能でマクロが止められていることがあります。ファイルを右クリック →「プロパティ」→「全般」タブの下の「セキュリティ: 許可する」にチェック →「OK」で解除できます。

### 既存の Excel ツールから始める

今ある `.xlsm` などのツールを、そのまま xlCode で編集できるように取り込めます。

1. 「ブック未作成のディレクトリ」で取り込み先のフォルダの **＋** を押します。
2. 「**既存の Excel ツールから作成…**」を押し、ツールのファイル（`.xlsm` / `.xlsb` / `.xls` / `.xlsx` / `.xltm`）を選びます。
3. 取り込みが終わると、取り込んだシートの一覧と、取り込めなかったものの注意がブック画面に出ます。内容を確認してから Build してください。

取り込みの内容:

- 元のファイルはコピーしてから開くので、**変更しません**（開いたままでも取り込めます）。
- 画面・データのシートは、図形・ボタン・書式・入力規則を含めてそのまま残ります。
- 標準・クラスモジュールは `.bas` / `.cls`、ブック・シートのコードは `ThisWorkbook.cls` / `（シート名）.cls` として、ファイルに書き出してからシートにします（中身の無いものは省きます）。
- ユーザーフォームは `.frm` にし、配置を `Begin` 〜 `End` の形に書き起こします。画像、標準以外のコントロール、文字列の中の改行は取り込めません（注意として表示します）。
- 参照設定は `References.refs` にします（ほかのブックへの参照は取り込めません）。
- 取り込み先のフォルダに同じ名前のファイルがあると、何もせずに止まります。
- 最初の Build で、ビルド結果の場所に元のツールがあると、上書きの確認が出ます（元のファイルは `.xlcode/backup/` に残ります）。

「**空のブックを作成**」を選ぶと、フォルダ内の `.bas` / `.cls` / `.frm` / `References.refs` をシートにします。1 つも無ければ `Module1.bas` と `References.refs` の雛形を置きます。

## 設定

アクティビティバーの歯車で開きます。

### このパソコンの設定

**使う Excel** — [プロジェクトを開く](#1-プロジェクトを開く)を参照。選ぶとすぐに反映されます。

### このプロジェクトの設定

`.xlcode/config.json` に保存されます。変更したら右上の「**保存**」を押してください。

| 項目 | 内容 | 初期値 |
|---|---|---|
| ブックの置き場所 | 「フォルダを選ぶ…」で OneDrive 内の専用フォルダを指定すると、ブックだけをそこへ移動します。「ソースの中に戻す」で各フォルダの中へ戻します。この項目は「保存」を押さなくてもすぐに反映されます | ソースの各フォルダの中 |
| プロジェクトの種類 | 表示のみ（変更できません） | 最初のブックを作るときに選択 |
| Web 版の URL | Web 版で開くときの、ブックの置き場所の URL。空欄なら OneDrive の設定から自動で求めます。自動で開けないときだけ入力します（例: `https://contoso-my.sharepoint.com/personal/me_contoso_com/Documents/shop`） | 空欄（自動） |
| 省略検知 | 「◯% 以上減ったら確認（前回 ◯ 行以上のファイルが対象）」 | 30% / 10 行 |
| Prettier で整形する | JavaScript・TypeScript・CSS・JSON・HTML・Markdown・YAML など、Prettier が対応する形式を整形します。プロジェクトの `.prettierrc` があれば従います。VBA モードでは表示しません | オン |
| 行末の空白を削除する | Markdown は対象外 | オン |
| Build / Sync の前に Git へ自動コミットする | オフにすると、自動コミットも未コミットの確認もしません | オン |

## 文字コードと改行

Excel のセルには文字しか入らないので、xlCode がファイルごとの文字コードと改行を覚えておき、Build のときに元の形式で書き戻します。ブック画面の「形式」列で確認できます。

- 読めるもの: UTF-8、UTF-8（BOM 付き）、UTF-16 LE（BOM 付き）、Shift_JIS。改行は LF / CRLF
- 既存のファイルは、元の形式のまま保存します。
- Excel で新しく作ったファイルは、拡張子で決めます。

| 拡張子 | 文字コード | 改行 |
|---|---|---|
| `.bat` `.cmd` `.vbs` | Shift_JIS | CRLF |
| `.ps1` `.psm1` `.psd1` | UTF-8（BOM 付き） | CRLF |
| `.reg` | UTF-16 LE | CRLF |
| `.bas` `.cls` `.frm` `.refs`（VBA モード） | Shift_JIS | CRLF |
| それ以外 | UTF-8 | LF |

Shift_JIS のファイルに、Shift_JIS で表せない文字（絵文字など）を書くと、Build はファイルを書き換えずにエラーで止まります。

## 困ったとき

### Build / Sync が押せない

ボタンにマウスを乗せると理由が出ます。

- **デスクトップ版 Excel で開かれている**: Excel でブックを閉じてください。閉じると数秒で自動的に押せるようになります。閉じても変わらないときは、サイドバーの「再読み込み」を押してください。Excel が異常終了すると、ブックと同じフォルダに `~$（ブック名）` というファイルが残ることがあります。Excel をすべて閉じてから、このファイルを削除してください。
- **処理中**: 終わるまで待ってください。

### 「〜行目が文字列ではありません」

Excel がセルの内容を数値・日付などに自動変換しています（例: `007`、`1-2`、`=` で始まる行）。そのセルの書式を「文字列」にするか、先頭に `'` を付けて入力し直してください。

### 「シート名エラー」「ファイル名エラー」

[シート名の決まり](#シート名の決まり)に合わない名前があります。シート名またはファイル名を直してください。ファイルを対象外にしたい場合は `.gitignore` に追加します。

### 「生成先が重複するシートがあります」「大文字小文字だけが異なるファイルがあります」

`App.ts` と `app.ts` のように、大文字小文字だけが違う名前は使えません。どちらかの名前を変えてください。

### 「〜と DEL_〜 が両方あります」

同じファイルについて、ふつうのシートと `DEL_` 付きのシートが両方あります。どちらかを削除してください。

### 「同一ディレクトリに複数の .xlcode.xlsx があります」

1 つのフォルダに編集用ブックは 1 冊だけです。不要なほうを削除（または移動）してください。

### 「ブックの複製があります」

OneDrive の同期がぶつかり、`ブック名-PC名.xlsx` のような複製ができています。複製の中身を確認して必要な変更を元のブックに移し、複製を削除してください。

### 「ブックに対応するソースのフォルダがありません」

ブックの置き場所にあるブックに対応するフォルダが、プロジェクトにありません。ソースのフォルダを移動・削除した場合は、ブックも同じ構成に合わせるか、不要なブックを削除してください。

### 「ブックのパスが 〜 文字あり、Excel が開ける 218 文字を超えています」

Excel は長すぎる場所のファイルを開けません。フォルダを浅くするか、名前を短くしてください。

### 「〜を整形できませんでした」

コードに文法の誤りがあり、Prettier が整形できませんでした。警告だけなので Build / Sync はできます（整形せずに保存します）。コードを直すと警告は消えます。

### 「〜が途中で開かれたため中断しました」

Build / Sync の途中でブックが Excel で開かれました。メッセージのとおり、どこまで書き換えたかが表示されます。Excel を閉じてから、もう一度実行してください。

### 「.xlcode/state.json が壊れています」

xlCode の記録が読めないため、Build / Sync を止めています（黙って初期化すると、ファイルが衝突扱いになるため）。

1. `.xlcode/state.json.bak` があれば、`state.json` にコピーして戻します。
2. 無ければ `state.json` を削除すると初期化できます。ただし次の Build / Sync で、両側に差があるファイルは衝突扱いになります。

### Web 版で開けない

「Web 版の URL を特定できません」と出る場合は、ブックが OneDrive / SharePoint の同期フォルダの中にあるか確認してください。中にあるのに開けない場合は、[設定](#このプロジェクトの設定)の「Web 版の URL」に、ブックの置き場所のフォルダの URL（ブラウザで OneDrive のそのフォルダを開いたときのアドレス）を入力してください。

### Copilot がコードを省略する

「コードが大きく減っています」の確認が出たら、差分を見て、`// ...既存のコード...` のような省略が無いか確かめてください。省略されていたら「キャンセル」して、Copilot に「省略せずにファイル全体を書いて」と頼み直します。
`Agents.md` に「コードを省略しない」と書いておくのも効果があります。

### 間違えて Build / Sync してしまった

すぐなら「**元に戻す**」で取り消せます。もっと前に戻したい場合は、ソースコードは Git の履歴（自動コミット `xlcode: Build 前の自動コミット` など）から、ブックは OneDrive のバージョン履歴から戻してください。
